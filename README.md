# SageHarvest — Seed Production Monitor

A mobile-first front-end prototype for field officers and seed production managers.

## Open the prototype

Open `index.html` in a browser, or use the [live demo](https://rajavadlamani-png.github.io/seed-production-intelligence-platform/). The management workspace and field officer app view are both interactive.

## Current scope

- Role-specific dashboards for Field Officers (personal assignments), Territory Managers (assigned Field Officers), and Production Managers (consolidated state scope), plus an aggregator sample view.
- Territory and state comparisons of assigned farmers, measured acreage, on-track/follow-up status, and counts across all six inspection stages. The dashboards recalculate from current in-browser sample records.
- Production Manager master-list preview accepts `.xlsx`, `.xls`, and `.csv`, validates required farmer/field details, duplicate seasonal field numbers, assigned acreage, and TM-to-FO assignments, then adds valid rows to this browser session. It includes a downloadable CSV template and default team assignments.
- Each inspection stage records separate disease and pest observation grades (Excellent, Good, Average, Poor, or Not recorded). All role dashboards summarize the latest grades and recorded acres with color bands; missing grades remain unclassified.
- Production Manager planning cards and a stage-by-stage yield outlook framework. Target achievement likelihood and yield estimates are explicitly unavailable until approved seasonal targets and validated crop/hybrid yield assumptions are supplied; the demo does not invent forecast values.
- Synthetic hierarchy: Maharashtra Production Manager → two sample Territory Managers → four sample Field Officers → 12 sample farmers. Role filters are only UI demonstrations; they are not access controls.
- Editable Paddy baseline inspections across six screenshot-based reports: First Inspection, Vegetative, Pre Flowering, Flowering, Pre Harvesting, and Harvesting. Shared farmer, assignment, season, field number, area and SAP lot context is shown once per report.
- First Inspection includes conditional isolation follow-ups; “No” isolation or missing applicable answers create human-review flags. Pest/disease remarks and poor-purity reasons appear when relevant. These forms use Paddy screenshot fields; crop-specific rules remain unconfigured.
- Field officer GPS boundary capture and area measurement in acres, plus a clearly labeled sample walk for previewing the flow.
- Guided field app preview with a welcome screen, mobile-number entry, a clearly labeled demo verification code (`123456`), compact Today / Fields / Reports / More tabs, and one selected farmer/field at a time.
- Nearby-field suggestion can use the officer's location only when assigned field boundaries have been captured in the current browser session; otherwise officers choose from their assigned field list.
- Field Weather Watch requests device GPS coordinates first and uses Open-Meteo for current conditions and a seven-day forecast. The user can switch between device GPS and the selected farmer/village forecast at any time. The selected-village lookup is constrained to India and the field's state; if it cannot confidently locate the village, it reports that rather than silently choosing an unrelated place.
- The six inspection stages appear together as a stage navigator. Officers can preview later-stage fields and answer choices in read-only mode, but cannot enter or save those reports until the prior stage is completed. Saving a draft does not unlock the following stage. Completion state is only in-memory demo state and is not server-enforced.
- Each stage includes an expandable SOP snapshot beside the report fields. These reminders summarize what the current Paddy forms capture; they are not an approved technical SOP and contain no agronomic acceptance thresholds.
- Each inspection stage has an optional fertilizer/agrochemical application log for type, product, quantity, unit, and purpose. Entries remain in browser memory for this demo session.
- Each stage has optional field/leaf photo capture with a local preview. Photos are not uploaded, and AI pest/disease assessment is deferred and not connected.
- The field app has a separate read-only Satellite observations page, prominently linked as **Satellite validation report** near the top of More. It explains the future report contents and clearly states that satellite imagery and measurements are not connected or available.
- After all six reports are marked complete, the field officer can open a final field summary with net G.S. acres, dispatch challan (DC), STN, dispatch date, seed weight, moisture, quality status, and productivity per acre when both area and weight are entered.
- The field app includes an **Ask Ram** voice and conversational assistant preview, previewed on the welcome screen and in a prominent Sage Harvest green banner with an original illustrated assistant portrait across field-app tabs. Open it from that banner or persistent navigation. The officer can choose a language, use suggested field-work questions, and type a question to preview the chat layout. Voice capture and AI responses are not connected; the local chat displays an explicit unavailable notice and sends no messages to a service.
- Branded field app header and footer with the approved Sage Harvest wordmark and fixed mobile navigation.
- Separate parent seed lot fields for male M-1/M-2/M-3 and female parents, with browser QR scanning when supported; parent seed IDs and lots can prefill from a demo master upload in the current browser session; secure production lookup remains planned.
- Master-list import is a browser-only prototype preview. It does not save to a server and accepts invented sample records only; uploaded bank-account columns are ignored. Do not use real farmer or personal data on the public Pages demo.
- Shared Sage Harvest corporate logo, favicon, color palette, and typography. The source artwork is in `assets/`.
- Session-only **Templates & designations** workspace on the manager navigation: the six Paddy inspection stages are driven by stable stage metadata; demo users can rename a stage, relabel/reorder/hide/show/retire fields, set required flags, edit select options, add supported field types, and preview a mobile/desktop layout. Changes affect the in-browser report form while the page remains loaded and reset on refresh.
- Local designation/alias editor for Temporary Field Assistant (TFA), Field Officer, Production Officer, and Territory Production Lead (TPL). Titles and aliases are separate from platform role keys and permissions; all role mappings intentionally remain unmapped.
- The configurable workspace shows the approved initial pilot target: Paddy, Telangana, Karimnagar, Rabi 2026–27 (expected to start November 2026). It does not invent village, grower, or field master data. The current synthetic Maharashtra roster remains a separate demo dataset.
- Automated Chromium browser checks for login, pilot scope, six stages, stage rename, field hide/show/add, preview layouts, designation boundaries, navigation and mobile overflow passed in GitHub Actions on commit `a023aab9e8a9311fe59625cddd6302215b779271`. The full manual checklist and a separate hosted preview remain outstanding; see [`docs/BROWSER_ACCEPTANCE_CHECKLIST_V1.md`](docs/BROWSER_ACCEPTANCE_CHECKLIST_V1.md).
- Template lifecycle states are shown as governance guidance only. Approval, scheduling, publication, immutable version storage, audit history, historical-submission pinning, and server validation are not implemented in this static prototype.

All figures, locations and observations are illustrative. The mobile-number and demo-code screens are not authentication and do not send an OTP. The prototype does not include server-side persistence, production data, a backend, database or secure production Excel import, SAP integration, satellite feeds, or AI models. Weather Watch uses Open-Meteo with device GPS permission and a clearly labelled selected-field fallback. GPS capture runs in the browser only while the page is open; captured points and area are not sent to a server or retained after refresh. Nearby matching requires assigned field boundaries in the current browser session and does not run against production maps. Inspection entries, chat messages and selected photo previews exist only in the current browser session; photos are not uploaded or analysed, and chat messages are not sent to an AI. Satellite observations are unavailable until a provider and secure data service are connected. Ask Ram is a UI preview only: microphone access, multilingual speech, and Google AI answers are not implemented. The final summary uses field-officer entries and is a prototype report, not a verified production document. Stage completion is a demo workflow gate, not a server-enforced permission. Do not enter or upload real farmer, mobile, or bank data on the public demo.

## Next stage

Confirm crop-specific isolation rules, seasonal acreage and production targets, and crop/hybrid yield assumptions with the production team before adding compliance or predictive forecasts. The six Paddy inspection report forms are the current baseline. Other crops should use separately confirmed, configurable field definitions. GitHub Pages can host this front-end prototype; production records and integrations require a separate secure backend.
